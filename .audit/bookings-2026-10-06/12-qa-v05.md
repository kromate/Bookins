## Bugs

### BUG-1 (Medium): removed time off shows up as a client in Contacts
- Repro: Availability -> add time off (reason "Dentist") -> Remove -> Remove time off. Open Contacts.
- Expected: no contact for time off (contract: "Bookings, Contacts, Index, Insights must exclude time off"). Count should stay 6.
- Actual: a contact "Dentist" (No email, No phone, 1 booking) appears; header "7 contacts". The Bookings page correctly hides it.
- Cause: `removeTimeOff` sets `status: 'cancelled'` (booking.js ~653), and `isTimeOff` only matches `status === 'blocked'` (booking.js:30), so removed time off passes the filter. Bookings.vue:32 additionally checks `service_id === TIME_OFF_SERVICE_ID`; Contacts and Insights do not.
- Suspect: pages/Contacts.vue:37 (`!isTimeOff(item)`), pages/Insights.vue:36; root cause booking.js:30 / removeTimeOff. Fix: also treat `service_id === 'time-off'` as time off in `isTimeOff`.
- Insights: same filter, so a removed time-off record in the selected period would likely inflate cancelled counts and cancellation rate. I could not demonstrate this (my API-driven removal did not refresh the UI state), so it is unconfirmed.

### BUG-2 (Low): stale version chip in Settings
- Actual: Settings header shows "Bookins v0.4.0 candidate". `package.json` and `.goalmatic/app.json` are 0.5.0.
- Suspect: pages/Settings.vue:446.

### BUG-3 (Low): variable chips display with the wrong case
- Repro: Settings -> Messages to your guests. Chips render as `{{Guest_name}}`, `{{Booking_link}}` etc.
- Expected: `{{guest_name}}` (variables are case-sensitive; inserted text is lowercase). Cause: inherited `.chip` text-transform: capitalize (css/global.css:592 area; `.var-chip` at pages/Settings.vue:779 does not reset it). Computed `text-transform` on the chip is `capitalize`. Misleading, not functionally harmful.

### BUG-4 (Low): FR time format inconsistent
- /book slot list shows `9:00` while step 3 and confirmation show `09:00` (and 24h `15:00` elsewhere). Pages/Book.vue slot label formatting vs. details formatting.

### BUG-5 (Info / Low): Demo mode disables read-only controls
- In Demo, Settings "Copy link", "Download PNG", "Copy button code" are disabled (all 918 controls disabled; enabled list is empty). These are not mutations. Harmless but reduces the demo.

### BUG-6 (Low / possible gap): service location is never shown to guests
- Service `location` is only used in the `{{location}}` message variable. /book (pages/Book.vue has no reference to location) and the .ics (no LOCATION line) ignore it, though README lists location as a service feature. If guests are expected to see it, this is missing.

### Notes (not app bugs)
- The mobile nav drawer carries `role="dialog"` while closed (offscreen at x=-277), so a naive `[role=dialog]` query finds it first. Possibly an accessibility smell; not investigated further.
- Past sample booking "45 days ago, confirmed" (history.js last row) stays "confirmed" forever; harmless, but it inflates the confirmed count for Chiamaka and appears as a stale confirmed record in Past.

## Could not exercise / limits
- Hosted (non-localhost) runtime, real Goalmatic Tables, real guest actions, calendar/connected-provider flows: not testable with the key disabled.
- Hard reload persistence for owner data (templates, notes, locations): local preview is in memory by design, so I verified persistence only across in-app navigation. Locale persistence was verified across a true reload.
- Real keyboard focus/typing: all input was via DOM events. Template chip insertion into the subject field depends on `@focus` tracking and needed a manually dispatched focus event; verify with real focus.
- End-before-start time-off error text (blocked natively by `min`); the 60-day maximum; repeat-weekly of 12; DST/timezone edges for non-Lagos schedules.
- Overview "No-show" button (only Completed was clicked there); No-show was verified in the Bookings dialog.
- Insights cancellation inflation from removed time off (see BUG-1).
- Console errors for the opening ~10 minutes (hook lost on a reload) and for Demo walk-through guide (DemoGuide / /demo/guest) were not examined.
- Mobile 375: measured inside an iframe because another process kept navigating/resizing the shared preview tab to a different localhost port. The inner viewport was a true 375px; touch behaviour and the real mobile browser chrome were not tested.
- Screenshots: the snapshot tool errored on this client, so no visual review (contrast, spacing) was done.
